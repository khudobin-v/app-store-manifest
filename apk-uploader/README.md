# apk-uploader — загрузка готового APK в личный магазин из браузера

Веб-интерфейс для случая «есть APK, исходников нет»: перетащили файл — он
разобран, залит в GitHub Release и добавлен в витрину `apps.json`.

React + TypeScript + Vite, без бэкенда: всё делается в браузере вашим
GitHub-токеном. Альтернатива `release-kit/tools/publish-apk.sh` — тот же
результат, но без Android SDK и терминала.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 21 тест
npm run build    # статика в dist/
```

`dist/` — обычная статика, её можно положить на GitHub Pages. Но помните, что
страница работает с вашим токеном: чем меньше мест, где она опубликована, тем
лучше. Локального `npm run dev` достаточно.

## Что происходит при загрузке

1. **APK разбирается прямо в браузере.** `AndroidManifest.xml` внутри APK —
   бинарный AXML; парсер в `src/apk/axml.ts` достаёт `packageName`,
   `versionCode`, `versionName`. Тесты сверяют результат с `aapt2 dump badging`.
2. Считается sha256 (WebCrypto) и размер — ровно те значения, которые потом
   проверит клиент магазина перед установкой.
3. Проверяется наличие подписи (v1 по `META-INF/*.RSA`, v2/v3 по блоку подписи).
   Неподписанный APK Android не установит.
4. **Сначала читается витрина и проверяется versionCode**, и только потом
   заливается файл: иначе при повторной версии в хранилище остался бы APK,
   которого нет в витрине.
5. APK уходит ассетом в Release репозитория-хранилища, запись — в `apps.json`
   через Contents API.

## Что нужно указать

| Поле | Что это |
|---|---|
| Репозиторий витрины | `владелец/app-store-manifest` |
| Репозиторий-хранилище | куда класть APK, по умолчанию `владелец/app-store-uploads` |
| Токен | fine-grained PAT с **Contents: read and write** на оба репозитория |

Токен хранится только в `sessionStorage` вкладки и отправляется только на
`api.github.com`/`uploads.github.com`. Закрыли вкладку — забылся.

## Ограничения

- **Название и иконка.** В большинстве APK `android:label` и `android:icon` —
  ссылки на ресурсы, а разворачивать `resources.arsc` в браузере оверкилл.
  Если название прочитать не удалось, поле подставляется из `packageName` и
  правится вручную; иконку можно выбрать файлом (PNG).
- **Подпись не проверяется по цепочке** — это не замена `apksigner`, а защита
  от «залил не тот файл». Следующая версия должна быть подписана тем же ключом,
  иначе Android не поставит обновление поверх.
- `versionCode` берётся из APK: повтор или откат витрина отклонит (то же
  правило, что в `update_manifest.py`).

## Структура

```
src/
├── apk/axml.ts      разбор бинарного AndroidManifest.xml
├── apk/apk.ts       чтение APK: метаданные, sha256, признак подписи
├── manifest.ts      правила apps.json (порт update_manifest.py на TypeScript)
├── github.ts        клиент GitHub API: Releases + Contents
├── publish.ts       сценарий публикации
└── App.tsx          интерфейс
```

Тесты: `src/apk/apk.test.ts` (сверка с `aapt2` и `shasum` на настоящих APK),
`src/manifest.test.ts` (те же проверки, что у python-версии, включая отказ
при дубликате `versionCode`).
